# Архитектура проекта u-not

## Обзор

u-not - это приложение для мониторинга новых дорам на различных платформах с возможностью уведомления через Telegram. Проект построен на основе модульной архитектуры с четким разделением ответственности между компонентами.

## Структура

```
src/
├── core/                  # Ядро приложения
│   ├── config/            # Конфигурация и валидация
│   │   └── schema.ts      # Zod схемы и валидация
│   ├── drama/             # Логика работы с дорамами
│   │   ├── fetcher.ts     # Загрузка данных из источников
│   │   └── storage.ts     # Хранение и обновление списка дорам
│   └── index.ts           # Экспорт ядра
│
├── services/              # Внешние сервисы
│   ├── telegram/          # Telegram интеграция
│   │   └── notifications.ts # Отправка уведомлений
│   └── vk/                # VK интеграция
│       └── notifications.ts # Отправка уведомлений в беседу
│
└── index.ts               # Точка входа приложения
```

## Компоненты

### Core

#### config/schema.ts
- **Ответственность**: Валидация конфигурационного файла
- **Технологии**: Zod для валидации схем
- **Типы**:
  - `Source`: Конфигурация источника данных
  - `Config`: Общая конфигурация приложения
  - `ChatId`: ID чата Telegram

#### drama/fetcher.ts
- **Ответственность**: Загрузка данных из внешних источников
- **Функции**:
  - `fetchDramasFromSource()`: Получение данных из API
- **Особенности**:
  - Обработка ошибок и время ожидания
  - Поддержка пользовательских заголовков
  - Извлечение названий, постеров и ссылок через JSONPath
  - Нормализация `{SIZE}` в URL постера и относительных ссылок

#### drama/storage.ts
- **Ответственность**: Работа с файлом drama-list.md
- **Функции**:
  - `getExistingDramas()`: Чтение существующих дорам
  - `appendNewDramas()`: Добавление новых дорам
  - `getTimestamp()`: Генерация метки времени

### Services

#### telegram/notifications.ts
- **Ответственность**: Отправка уведомлений через Telegram
- **Функции**:
  - `sendTelegramNotification()`: Отправка сообщения в чат
- **Особенности**:
  - Поддержка HTML форматирования
  - Обработка ошибок для каждого чата

#### vk/notifications.ts
- **Ответственность**: Отправка уведомлений в беседу VK
- **Функции**:
  - `sendVkNotification()`: Отправка сообщения в беседу через messages.send
- **Особенности**:
  - Raw fetch к api.vk.com (без библиотек)
  - `random_id` для предотвращения дубликатов (монотонный счётчик)
  - Обработка ошибок для каждой беседы
  - Загрузка постера: скачивание → `photos.getMessagesUploadServer` → multipart-аплоад → `photos.saveMessagesPhoto` → attachment `photo{owner}_{id}_{key}`
  - При провале загрузки постера сообщение отправляется текстом без фото
  - Нейтрализация VK-разметки (`**`, `__`, `[url|text]`) в названиях дорам и источников
  - User-Agent из конфига передаётся при скачивании постера

## Поток данных

1. **Загрузка конфигурации**: Чтение и валидация config.json
2. **Получение существующих дорам**: Чтение drama-list.md
3. **Загрузка новых данных**: Вызов API для каждого источника
4. **Фильтрация**: Сравнение с существующими дорамами
5. **Обновление файла**: Добавление новых дорам в drama-list.md
6. **Уведомления**: Отправка сообщения через Telegram и VK (если настроено)

## Конвенции

### Наименование
- **Файлы**: kebab-case (например, `fetcher.ts`)
- **Функции**: camelCase (например, `fetchDramasFromSource()`)

## Best Practices

1. **Модульность**: Каждый файл отвечает за одну область ответственности
2. **Типизация**: Строгие типы TypeScript для всех данных
3. **Обработка ошибок**: Гранулярная обработка на уровне функций
4. **Логирование**: Информативные сообщения для отладки
5. **Документация**: JSDoc для всех публичных интерфейсов

## Масштабируемость

### Добавление нового источника
1. Создать новый модуль в `src/core/drama/`
2. Реализовать интерфейс `SourceFetcher`
3. Обновить конфигурацию для поддержки нового типа

### Добавление нового сервиса уведомлений
1. Создать директорию в `src/services/`
2. Реализовать интерфейс `NotificationService`
3. Интегрировать в основной поток
